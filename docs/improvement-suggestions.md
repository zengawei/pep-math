# pep-math 项目改进建议

> 生成时间：2026-08-18  
> 基于 Plan 6 完成后的项目状态评估

---

## 1. 内容质量与教学设计

### 当前问题
- 所有题目为"自编"，缺乏高考真题和经典题型
- 难度分级粗糙（仅 basic/medium/hard）
- 缺少解题策略和方法论总结
- 知识点之间缺少学习路径建议

### 改进方案
- 增加"高考真题"分类，收录近 5 年典型考题
- 细化难度：入门 → 基础 → 巩固 → 提升 → 挑战（5 级）
- 每个章节添加"学习方法"板块：
  - 常见题型归纳
  - 解题模板（如"求导数单调区间的 4 步法"）
  - 易错点清单
- 知识点页面增加"学习路径"：
  - 前置知识掌握自测（3 道快速判断题）
  - 推荐学习顺序（如：先学函数性质再学导数）

---

## 2. 用户体验与交互

### 当前问题
- 无暗黑模式
- 无学习进度追踪
- 习题只能"展开/收起"，缺少渐进式提示
- 知识图谱交互有限（仅点击跳转）

### 改进方案
- 添加暗黑模式（Tailwind dark: 类已支持，需实现切换）
- 习题增加"提示"按钮：
  - 第 1 次点击：显示解题思路（不显示答案）
  - 第 2 次点击：显示第一步
  - 第 3 次点击：显示完整解答
- 添加"收藏夹"功能（localStorage）：
  - 收藏难题、易错题
  - 生成"我的错题本"页面
- 知识图谱增强：
  - 悬停显示知识点摘要
  - 支持缩放和平移（Cytoscape 已支持，需启用）
  - 高亮当前知识点的前驱/后继路径
- 添加"学习进度"：
  - 记录已完成的习题（localStorage）
  - 章节完成度百分比
  - 知识点掌握度热力图

## 3. 性能优化

### 当前问题
- KaTeX 字体文件多（60+ 个），首次加载慢
- Cytoscape.js 包体积 446KB
- 156 个页面全量构建，增量构建不支持

### 改进方案
- KaTeX 优化：
  - 仅加载用到的字体子集（font subset）
  - 使用 font-display: swap 避免 FOIT
  - 考虑服务端渲染 KaTeX（Astro 支持）
- 代码分割：
  - Cytoscape 仅在知识图谱页面加载（已实现）
  - 习题 JSON 按需加载（已实现）
  - 考虑将 SearchBox 组件懒加载
- 构建优化：
  - 使用 Astro 的 incremental builds
  - 缓存 pagefind 索引（如果内容未变）
- 图片优化：
  - 如果有图表，使用 WebP/AVIF 格式
  - 懒加载非首屏图片

## 4. 可访问性（Accessibility）

### 当前问题
- 未检查 ARIA 标签
- 数学公式对屏幕阅读器不友好
- 键盘导航可能不完善

### 改进方案
- 为 KaTeX 公式添加 aria-label：
  - 例：<span aria-label="x 的平方">x^2</span>
- 知识图谱添加键盘导航：
  - Tab 键切换节点
  - Enter 键激活
- 颜色对比度检查：
  - 难度标签颜色是否符合 WCAG AA 标准
  - 提供高对比度模式
- 添加跳转链接（skip links）：
  - 跳过导航直达内容

---

## 5. SEO 与可发现性

### 当前问题
- 缺少 meta description
- 无 Open Graph 标签（社交分享无预览）
- 无 sitemap.xml（虽然有 Astro 插件可用）
- 无结构化数据（Schema.org）

### 改进方案
- 每个页面添加 meta description：
  - 知识点页面："{知识点名称}的定义、公式、例题和习题"
  - 章节页面："{教材名} 第{N}章 {章节名} 的习题和知识点"
- 添加 Open Graph 标签：
  - og:title, og:description, og:image
  - 设计一个分享封面图（1200x630px）
- 生成 sitemap.xml：
  - 使用 @astrojs/sitemap 插件
  - 提交到 Google Search Console
- 添加结构化数据（JSON-LD）：
  - Course、Lesson、Question 等 Schema.org 类型
  - 有助于 Google 理解内容结构

## 6. 测试覆盖

### 当前问题
- 87 个测试主要是单元测试和集成测试
- 无端到端（E2E）测试
- 无视觉回归测试
- 内容验证测试只检查结构，不检查数学正确性

### 改进方案
- 添加 Playwright E2E 测试：
  - 测试习题点击展开流程
  - 测试搜索功能
  - 测试知识图谱筛选
  - 测试移动端响应式
- 添加视觉回归测试（Playwright screenshots）：
  - 关键页面截图对比
  - 检测意外的样式变化
- 数学正确性验证：
  - 编写脚本验证所有公式的 LaTeX 语法
  - 抽样验证答案正确性（可用 SymPy 等工具）
- 测试覆盖率报告：
  - 使用 Vitest --coverage
  - 目标：核心组件 > 80%

## 7. 内容管理

### 当前问题
- 添加内容需要手动创建多个 Markdown 文件
- 无内容管理界面
- 无协作编辑支持

### 改进方案
- 创建内容脚手架脚本：
  ```bash
  npm run create-section -- --textbook=selective-3 --chapter=17 --section=1
  ```
  自动生成 definition/exercise/example 模板文件
- 添加内容验证预检：
  - 提交前自动运行 validate
  - 检查公式语法、知识点引用
- 考虑使用 CMS（如 Decap CMS）：
  - 非技术用户可以通过 Web 界面编辑内容
  - 通过 Git 提交变更
- 添加内容模板库：
  - 常见题型模板（选择题、填空题、解答题）
  - 知识点定义模板

## 8. 移动端体验

### 当前问题
- 未验证移动端布局
- 知识图谱在小屏幕上可能难以操作
- 触摸交互未优化

### 改进方案
- 响应式测试：
  - 使用 Chrome DevTools 测试 375px/768px/1024px
  - 验证导航菜单在移动端的折叠行为
- 知识图谱移动端优化：
  - 小屏幕默认显示简化视图（仅显示当前教材）
  - 支持双指缩放和触摸拖动
- 触摸交互优化：
  - 增大点击区域（至少 44x44px）
  - 习题展开/收起添加手势支持
- PWA 支持：
  - 添加 manifest.json
  - 支持离线访问（Service Worker）
  - 可"添加到主屏幕"

- 无错误报告机制
- 无法知道哪些知识点最难

### 改进方案
- 添加匿名分析（可选）：

  - 每个页面底部"这个页面有帮助吗？"
  - "报告错误"按钮（链接到 GitHub Issues）
- 生成学习分析报告：
  - 哪些知识点被查看最多
  - 哪些习题错误率最高
  - 用于优化内容质量
